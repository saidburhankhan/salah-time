## R3a: app findings from r3-findings.md

Codex worker C7 wrote most of this and hit its usage limit before finishing. Claude checked its diff against every app/ finding, fixed a racy test, and finished the rest.

- Core client: reads are coalesced only when the method and the full RPC params match and no changed notification has arrived since (a read generation). A read finishes with the callbacks on the live in-flight request (`completeRpc` moves `m_current`), so a caller coalesced after dispatch is always answered. Offline writes no longer build CLI commands: every mutation goes through stdio `salah rpc` (hello, then the same frame the socket would get), so session.start/log/stop/edit keep their target, date, minutes, values, note, epic, explicit clears (null note, `{}` values) and `expected_version`. Offline stats.get/stats.series/stats.table pass every filter through to the CLI (`--epic`, `--min-minutes`, `--min/--max METRIC=V`, `--group`). A failed stats.get or stats.table clears the old result.
- Writes: Done on a running item sends one session.log tick (the server stops the timer in the same transaction). tickItem on an item that already has a tick answers the waiting dialog (ok, or an error saying the ratings and note were not saved). session.edit sends the version captured when the editor opened (Notes, Epic page, Today session rows). The Log date comes from the originating view: Today rows send the browsed day, the Epic page sends none.
- SessionPrompt: each submit carries its own op_id and only the matching sessionWriteFinished closes or fails it; the pause form follows status.max_minutes for its session and re-checks before submitting.
- Changed notifications emit `reportsInvalidated`; the visible Statistics tab, the task picker (items.list) and the open Epic page reload.
