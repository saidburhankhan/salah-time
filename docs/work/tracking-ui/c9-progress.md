## 2 — goals

- Backend (`app/src/backend_goals.cpp`): `goals` (goals.list, today's progress, refreshed by `loadSettings`, so every `changed` notification and entity save reloads it, including the `goals` scope), `goalHistory`/`goalHistoryId` (goals.history over the longest span, 730 days ending today), and `addGoal`/`editGoal`/`endGoal`/`removeGoal`. Writes go through `mutateEntity` (fresh `op_id`; edit, end and remove send the row's `expected_version`), reload the list, and emit `goalWriteFinished`. A conflict reloads the list. At most one scope id is sent, none means all work; a direction is sent only with a metric; a zero target never leaves the app.
- QML (`app/src/qml/goals/`): `GoalRow` (muted bar: green met, amber short of an at-least target, red over an at-most limit; a check once met; inline Edit target, End with confirm, Remove while in the first period, optional History button), `GoalForm` (period, Minutes or a metric chip, At least/At most for a metric, target, Add goal), `GoalsSection` (the editors' section: the scope's active goals plus a collapsed add form; metric chips follow the protocol: the task's own asks, else the project's asked metrics, built-ins for all work), `GoalHistory` (period, value, target, met table with "Met in N of M periods"), `GoalText.js`. All dynamic strings are `Text.PlainText`; a missing value shows "—", never hidden.
- Placement: Goals section in the project editor (Settings → Projects, below Epics), the Epic page (card above Notes) and the task editor (right column under the preview, existing tasks only, also for backlog tasks); sidebar entry "Goals" (page 6, new `goals` icon, header title) with `GoalsPage`: Today and This week groups with "N of M met", a progress row per goal naming its scope, History per goal (one open at a time, closed after any goal write because an edit gives the goal a successor id), and an "Add a goal for all work" form.
